# Beach sweep — figure guide

Run: `beach_sweep_20260616_182606` · **360 episodes**, 0 errors, **$51.08** total.

Swept worlds: models = {Haiku, Sonnet, Opus} × `grid_size ∈ {4,5,6}` ×
`papers_needed ∈ {2,3,4,5}`, **10 reps/cell**. Per cell, `shovel_durability` and
`total_rocks` are derived from grid (`round(0.4·grid²)`). Each figure is regenerated by:

```sh
python -m scripts.analyze_beach_sweep runs/beach_sweep_20260616_182606/episodes.jsonl
```

The world is a brute-vs-tool task: collect all `papers_needed` scraps → a **map**
forms (the reusable tool) → read it → walk to the treasure → dig once. The
alternative is brute-force digging until the shovel breaks. The instrumentation
tracks three steps of the tool pipeline — **build** (collect all scraps),
**use** (read the map), **win**.

## Headline finding

Building the tool is **not** the differentiator — *exploiting* it is. All three
models collect the scraps at similar rates (~0.6–1.0). But:

- **Sonnet / Opus**: P(win | built) ≈ **1.00** — when they build the map they
  cash it in. They skip the map only when grinding is a sure thing (mostly at
  high `papers`, where building is costliest) — a deliberate build-vs-grind choice.
- **Haiku**: P(win | built) ≈ **0.33–0.86** — it assembles the map and then
  often fails to read it (`use_map` ≈ 0.1–0.4) and loses anyway. The tool sits
  idle in its inventory.

## Figures

### Disposition / pipeline

- **`fig_beach_build_rate.png`** — Map-build rate per model, 3×4 grid (rows =
  grid, cols = papers), bars with Wilson 95% CIs. Shows building is roughly
  uniform (~0.6–1.0) across models and worlds.
- **`fig_beach_funnel.png`** — The **build → use → win** pipeline: three bars per
  model (P(built), P(used map), P(won)) per (grid, papers) cell. The key
  diagnostic: Haiku's orange "use" bar collapses far below its blue "build" bar
  in *every* world; Sonnet/Opus keep build ≈ use ≈ win.
- **`fig_beach_outcomes.png`** — Stacked 2×2 outcome bars (built+won / built+lost
  / brute+won / brute+lost) per model, tiled per (grid, durability) cell.

### Rates vs the build-margin axis

- **`fig_beach_rates.png`** — Win rate and build rate vs `shovel_durability`
  (≈ grid here), one dodged series per model with Wilson error bars.
- **`fig_beach_efficiency.png`** — Mean total actions and mean digs vs durability
  per model (the cost view of build-vs-grind).

### Win-rate surfaces (heatmaps: papers × grid, 1×3 Haiku/Sonnet/Opus)

All use the seaborn **`vlag_r`** colormap centered at 0.5 — **blue = success,
red = failure** — unless noted.

- **`fig_beach_win_heatmap.png`** — Raw overall **P(win)** per cell. Haiku
  pale/red (0.30–0.80); Sonnet & Opus blue (0.70–1.00).
- **`fig_beach_win_heatmap_smoothed.png`** — Same P(win), but each cell **borrows
  strength from neighbors**: pools its own + adjacent cells (Chebyshev radius 1)
  and bootstraps (2000 reps, episode-level) for a stabilized estimate with a
  ±95% half-width annotated. Reveals the clean papers-axis trends buried in the
  noisy n=10 raw cells (Haiku degrades as papers rise; Opus mildly improves).
- **`fig_beach_built_heatmap.png`** — **P(all scraps collected = map built)** per
  cell, over built/total. Uniformly blue (~0.6–1.0) for all three models —
  building is not where they differ.
- **`fig_beach_win_given_built.png`** — **P(win | map built)** per cell, over
  wins/built — how well a model *exploits* the tool once it has it. Sonnet =
  1.00 everywhere; Opus ≈ 1.00; **Haiku 0.33–0.86** (the failure isolated).

### Derived / decomposition heatmaps

- **`fig_beach_win_via_built.png`** — Cell-wise **P(win|built) × P(built) =
  P(win ∧ built)**: the probability of winning *through* the map (tool-path win
  rate). vlag_r centered 0.5.
- **`fig_beach_win_via_built_minus_win.png`** — The product **minus** P(win) =
  `P(win∧built) − P(win) = −P(win without the map)`: the negated brute-force win
  rate. Diverging vlag_r centered at 0 (auto-scaled): `+0.00`/white = every win
  came via the map; red = the model won some games by grinding. The *capable*
  models (Sonnet/Opus) show more red here — they can afford to grind.
- **`fig_beach_win_given_notbuilt.png`** — **P(win | map NOT built)**, **negated
  so it renders red**, over wins/not-built. Brute-force success rate when the map
  was skipped (gray = always built the map). Denominators are small (these models
  usually build). Sonnet/Opus hit −1.00 (win-by-grind-every-time) mostly at high
  papers; Haiku's rare map-skips are mostly just losses.
